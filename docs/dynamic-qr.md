# Динамические QR

Короткий адрес `/d/<slug>` вместо данных внутри кода: ссылку можно сменить
после печати, переходы считаются. Это единственная часть Qrix, которой нужен
сервер — сам генератор по-прежнему работает целиком в браузере.

## Что уже есть

| Слой | Файл | Что делает |
|---|---|---|
| Схема | `src/server/schema.ts` | запись кода, лимиты, константы |
| Хранилище | `src/server/store.ts` | интерфейс, файловый адаптер, Upstash Redis |
| Логика | `src/server/codes.ts` | создание, правка, пауза, удаление, скан, статистика |
| Лицензии | `src/server/license.ts` | HMAC-токены без аккаунтов |
| HTTP | `src/server/router.ts` | все маршруты, один обработчик |
| Функция | `api/[...path].ts` | обёртка Vercel |
| Локальный сервер | `scripts/dev-api.ts` | тот же обработчик, файловая база |
| Проверки | `scripts/check-dynamic.ts` | 50 проверок логики и живого HTTP |

## Маршруты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/d/<slug>` | редирект 302, счётчик, статистика дня |
| POST | `/api/codes` | создать код, вернуть его и ключ владельца |
| GET | `/api/codes?slugs=a,b` | список по известным адресам |
| GET | `/api/codes/<slug>` | один код (с ключом — свой, без ключа — публичный) |
| PATCH | `/api/codes/<slug>` | сменить адрес или поставить на паузу |
| DELETE | `/api/codes/<slug>` | удалить |
| GET | `/api/codes/<slug>/stats` | сканы по дням, страны, тип устройства |
| GET | `/api/health` | какое хранилище подключено |

Ключ владельца передаётся заголовком `x-qrix-key`, лицензия — `x-qrix-license`.

## Приватность

- Сам IP не сохраняется: только `sha256(соль | день | ip)`, и только чтобы
  не считать один телефон сотней сканов за сутки.
- Страна берётся из заголовка хостинга (`x-vercel-ip-country`), устройство —
  грубая группа из User-Agent: телефон, планшет, компьютер. Модель не пишем.
- Статистика по дням живёт 120 дней, записи кодов — пока код существует.
- Коды и лицензии не попадают в выдачу: у API и редиректа `X-Robots-Tag: noindex`.

## Владение без аккаунтов

При создании сервер выдаёт ключ (24 случайных байта). В базе лежит только
`sha256` от него, поэтому по базе ключ не восстановить. Клиент хранит ключи
локально; потерял — код работает дальше, но сменить ссылку уже нельзя.
Так не нужны ни почта, ни пароли, ни GDPR-согласие на аккаунт.

## Лимиты

- Без лицензии — 3 живых кода на ключ.
- С лицензией (`QR_LICENSE_SECRET` + подписанный токен) — без лимита.
- Создание: 20 в час с одного адреса. API: 120 запросов в минуту.
- Сканы: 120 в минуту с одного посетителя (защита от накрутки).

## Локальная разработка

```bash
npm run dev:api     # API на 127.0.0.1:8787, база в .qrix/dynamic.json
npm run dev         # Vite проксирует /api и /d на 8787
npm run check:dynamic
```

## Перед деплоем

Нужна внешняя база: у Vercel нет постоянного диска.

1. Создать Upstash Redis (бесплатный тариф), взять REST URL и токен.
2. В Vercel добавить переменные: `QR_DB_URL`, `QR_DB_TOKEN`,
   `QR_IP_SALT` (любая случайная строка), `QR_BASE_URL=https://qr-ix.com`,
   при включении платного режима — `QR_LICENSE_SECRET`.
3. Передеплоить.

Без `QR_DB_URL` функция поднимется на файловом хранилище во временном
каталоге: предпросмотр не упадёт, но коды будут теряться при перезапуске.
